# PC-2 执行前检查清单 v2.0

**建立：** 2026-10-18
**取代：** PC-1（保留为 v1，历史对照）
**强制规则：** 任何清理、归档、删除、合并、移出追踪动作前，必须逐阶段签核。缺一项不执行。

---

## 阶段 0：前置确认（3 项）

### P0-1 环境记录
- 记录：目录、分支、HEAD、工作区改动数
- 命令：`pwd && git branch --show-current && git rev-parse --short HEAD && git status --porcelain | wc -l`
- 通过标准：工作区改动数 = 0，或已明确知道脏文件是什么
- **细化（R1, 2026-10-18）**：区分三种改动性质
  - `M` 已修改源码：高风险，必须先查清为何改动
  - `??` 未跟踪新文件：低风险，确认内容无害后提交即可
  - `D` 已删除文件：高风险，必须先查清删除原因
  - 仅 `??` 文档/资源时，提交后即视为归零，不阻塞
- 不通过：先提交或 stash，再继续

### P0-2 影响范围声明
- 写明：动什么类型文件、预计数量、影响哪些目录
- 不写清楚不动手

### P0-3 权限与进程检查
- 检查：写权限、PM2/服务是否正在使用目标文件
- 命令：`pm2 list 2>/dev/null | head -5`
- 通过标准：无进程占用目标文件

## 阶段 1：安全核查（5 项）

### P1-1 引用检查（CA-1、CA-5）
- 命令：`grep -rn "<对象>" src public --include="*.ts" --include="*.tsx" --include="*.json" --include="*.css"`
- 通过标准：结果为 0，或已确认引用不构成依赖
- 不通过：保留，登记原因

### P1-2 级联影响检查（CA-6/7/8）
- 检查：被处理对象 import 的模块、引用的图片/类型，是否只有它使用
- 通过标准：无其他文件依赖被处理对象

### P1-3 敏感文件二次检查（CA-14）
- 命令：`git ls-files | grep -icE "\.env|\.key|\.pem|secret|credential"`
- 通过标准：被处理清单里敏感文件数 = 0

### P1-4 体积检查
- 命令：`du -sh <目标>`
- 通过标准：体积与预期一致，异常则排查

### P1-5 dry-run 完整清单（CA-3）
- 命令：`git ls-files | grep -E "<模式>"`（列出完整清单，不只数数量）
- 通过标准：清单逐条过目，无意外文件

## 阶段 2：执行规范（3 项）

### P2-1 最小化原则（D6）
- 一次只处理一类文件，不混合多类
- 不在一轮内叠两个仓库的变更

### P2-2 可回滚（CA-2、CA-12）
- 移出追踪用 `git rm --cached`，不用 `git rm`
- 磁盘文件必须保留
- 回滚命令写进提交说明

### P2-3 命令可复现（CA-20）
- 给出完整命令，不省略、不缩写
- 终端输出必须可复现

---

## 阶段 3：验证（3 项）

### P3-1 验证命令
- 每个执行步骤后，给出明确的验证命令
- 通过标准：验证输出与预期一致

### P3-2 回滚演练
- 关键操作前，先演练一次回滚命令
- 确认回滚路径真实可用

### P3-3 终端取证（D9）
- 执行输出原样贴回
- 以终端为准，不以口头结论为准

---

## 阶段 4：收尾（3 项）

### P4-1 台账回填（CA-17）
- 执行结果写入登记册：批次号、文件、原因、证据

### P4-2 提交规范（D10）
- message 模板：`<type>(scope): <subject>` + 变更清单 + `Refs: <编号>`
- 英文书写

### P4-3 冷却期（CA-19）
- 归档文件稳定 30 天或 N 次构建后才真删
- 期间保留在 _archive/

## 失败处理

| 失败阶段 | 回滚动作 |
|---|---|
| 阶段 0 | 无变更，直接停止 |
| 阶段 1 | 无变更，记录缺口 |
| 阶段 2 执行中断 | `git reset --hard <P0-1记录的HEAD>` |
| 阶段 3 验证失败 | `git reset --hard HEAD~1`，查原因 |
| 阶段 4 收尾失败 | 补记账，不改代码 |

## 附录：KP-8 bash 反引号陷阱（2026-10-18）

- **症状**：`node -e "..."` 里的反引号被 bash 当命令替换，报 `No command M found`
- **根因**：双引号内反引号触发命令替换，shell 先执行再传给 node
- **错误做法**：`node -e "text = \`M\` 已修改"`（反引号被吃）
- **正确做法**：
  1. 用 heredoc `cat > file.js << 'JSEOF'`（单引号阻止展开）写脚本文件，再 `node file.js`
  2. 或在 node 里用 `String.fromCharCode(96)` 构造反引号
  3. 写 markdown 时优先用 heredoc，不用 `node -e "..."`
- **验证**：`grep` 看目标文件，反引号完好
