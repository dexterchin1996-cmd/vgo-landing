# 代码审计规则（CA 系列）v2.0

**建立：** 2026-10-18
**版本：** v2.0（v1.0 仅 8 条，v2.0 扩为 20 条 7 组）
**强制规则：** 任何删除/归档/合并动作前，必须先读本文件，结论必须引用规则编号。

## 一、引用检测
- CA-1 零引用≠无用。查 7 种：静态 import / 动态 import() / lazy+dynamic / 配置驱动 / 全项目字符串（含 docs、scripts、根配置）/ 大小写变体 / 测试+Storybook
- CA-2 归档不删除。用 git mv 移入 _archive/，保留 git 历史，可回滚

## 二、等价性
- CA-3 归档前取证：大小、行数、最后修改、git 最近提交、全部引用来源
- CA-4 近似名双向核查：一活一死要标记；两活要查是否重复实现
- CA-5 功能等价性：查最后 commit 说明、曾被哪个页面引用、被谁替代、替代品是否覆盖功能、有无功能丢失风险

## 三、级联影响
- CA-6 查被归档文件自身 import 的模块，是否因此变成新的零引用
- CA-7 查它引用的类型、图片、样式是否只有它使用
- CA-8 查所在目录的 barrel/index.ts 是否受影响

## 四、价值判定
- CA-9 分四类：死代码（可归档）/ 未接线代码（问产品）/ 未来功能（登记保留）/ 示例模板（移 docs）
- CA-10 涉及用户可见功能，必须产品视角确认，不纯技术判断
- CA-11 不确定一律保留并登记，不猜不赌

## 五、执行规范
- CA-12 回滚路径必须写进命令或台账，可一键找回
- CA-13 归档目录命名 _archive/{类型}-{日期}/，附 README：清单、原因、替代品、回滚命令
- CA-14 归档前扫敏感信息（.env/key/token）和第三方许可证

## 六、验证
- CA-15 归档后跑 tsc --noEmit；环境允许再跑 build/lint，确认没破坏
- CA-16 复验零引用仍成立；随机抽 1 个归档文件做恢复演练

## 七、治理
- CA-17 每批归档写进登记册：批次号、文件、原因、证据
- CA-18 每次审计声明扫描范围与排除项
- CA-19 归档冷却期：稳定 30 天或 N 次构建后才真删
- CA-20 审计输出必须可复现，结论必须引用规则编号
